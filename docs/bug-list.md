# AidBot Bug 清单

## 2026-07-28

### 常见问题点击后只填入输入框，未直接发送
- 状态：已完成。“问一问”空会话中的常见问题按钮点击后会自动提交给模型，并复用正常提问的会话、流式回答和错误处理流程。
- 产品记忆：常见问题属于快捷提问入口，点击即发送，不需要用户再次点击发送按钮。

### 请求或提问失败时缺少明确错误或警告
- 状态：已完成。HTTP 错误和 SSE `error` 事件统一返回 `code`、`message`、`retryable`、`request_id` 和安全的 `details`，旧 `detail` 字段暂时保留兼容。
- 前端新增统一 `ApiError`，非 2xx 响应会读取后端错误正文，不再全部降级为“请求失败”。
- 登录页的访问码登录和管理员登录都必须通过统一错误文案转换网络异常，不得直接显示浏览器原生的 `Failed to fetch`、`NetworkError` 或 `Load failed`。
- 用户和管理员聊天在模型失败、检索失败、网络中断或超时时保留对应的助手消息位置并展示失败状态；用户主动停止显示“已停止生成”。
- 管理员失败状态展示错误码和请求 ID；内部异常文本、堆栈、token 与密钥不得返回客户端。
- 失败或停止状态提供“再次提问”入口。
- 产品记忆：错误和警告必须出现在用户正在操作的对象附近；聊天失败不能通过删除空消息静默处理。成功状态仍优先由页面结果表达，不额外增加成功提示。

### 知识库工作台存在重复信息和误删风险
- 状态：已完成。已移除创建知识库成功条、页面顶部“知识库管理/知识库详情”眉题和卡片左上角重复缩写标识。
- 知识库创建后卡片已经直接出现，不再额外显示“已创建 XX 知识库”成功条；导入和重新索引结果也统一由源文档、片段数和索引状态表达。
- 知识库卡片只保留产品线、知识库名称、说明、源文档数、知识片段数和更新时间，不添加与这些字段重复的装饰性文字卡片。
- 知识库删除按钮固定使用与确认弹窗一致的红色危险操作样式。
- 删除知识库前必须弹出确认界面，并明确提示源文档和知识片段会一并永久删除且无法恢复。
- 产品记忆：可从页面结果直接观察到的创建、编辑、删除动作不重复显示成功条；不可逆删除必须二次确认，危险按钮统一使用红色语义。
- 产品记忆：返回等用户熟悉的导航操作使用清晰的粗线条图标，不重复显示文字标签，但必须保留无障碍名称和悬停提示。
- 产品记忆：知识库卡片不展示重复的产品线标签；详情页返回箭头与标题同行并保持约一个字符间距；知识库名称和产品线统一通过详情页“编辑”弹窗维护，不再设置单独的“配置产品线”按钮。

### 全局成功提示冗余且删除确认不统一
- 状态：已完成。已清理知识库、反馈、访问码和用户聊天中的绿色成功提示；页面直接通过列表、状态、按钮文字或弹窗关闭反映操作结果。
- “已导入文档/生成知识片段”“单条知识已保存”“已重新索引”“反馈已标记”“聊天已清空”“反馈已提交”“访问码已创建/复制”等不再额外占用页面空间。
- 复制按钮和评分控件可以在控件自身显示“已复制”“已提交”等持久状态，这属于当前状态展示，不属于额外成功提示。
- 所有后端 `DELETE` 操作对应的前端入口都必须二次确认：单条会话、全部会话、知识库、单条知识文档和访问码。
- 访问码删除已从浏览器原生 `window.confirm` 统一为系统删除确认弹窗；单条知识文档删除也已接入同一确认弹窗。
- 产品记忆：成功结果优先由页面当前状态表达，不额外显示绿色成功条；错误信息必须保留；所有永久删除或批量清空操作必须先显示系统级确认弹窗。
- 产品记忆：知识源索引状态显示在片段数左侧；重新索引使用圆箭头图标，点击后图标旋转且状态变为“正在索引”，后端请求结束后停止旋转并显示“已建立索引”，不额外显示成功提示。

## 2026-07-27

### 前端聊天页面 Renderer 内存耗尽
- 状态：已完成。用户聊天页和管理员聊天页已增加流式请求超时、卸载自动中止和 reader 释放；用户已完成长会话回归。
- 浏览器出现 `Out of Memory`，Chromium Renderer 进程退出，DevTools 连接也随之断开。
- 当前现象与流式聊天请求长期 Pending 同时出现，前端会保留空的助手消息和未完成的请求状态。
- 期望：流式请求异常、超时或页面卸载时能够及时终止；即使后端没有返回 `final` 事件，前端也应在超时后释放状态并显示可重试错误。

### 聊天消息列表无上限，长会话渲染压力过高
- 状态：已完成。聊天页默认只渲染最近 80 条消息，并保留点击查看完整历史的入口；用户已完成长会话回归。
- `messages` 会持续追加当前会话的所有用户消息和助手消息，打开历史会话时也会一次性加载全部消息。
- 当前没有消息分页、虚拟滚动或单页消息数量上限，长时间使用后会持续增加 DOM、字符串和 React 渲染负担。
- 期望：为历史消息增加分页、虚拟滚动或合理的单页展示上限，并保留查看完整历史的能力。

### 流式回答每个增量都会重复解析全部 Markdown
- 状态：已完成。Markdown 渲染组件已 memo 化，流式增量会通过 animation frame 批量合并后再写入消息状态；用户已完成长会话回归。
- 每次收到 `answer_delta` 都会更新消息数组并重新渲染整个消息列表；已有助手消息会重复执行 Markdown 解析和行内格式解析。
- 长回答或多轮会话下会产生大量临时字符串和渲染计算，可能放大 Renderer 内存占用并导致页面卡顿或 OOM。
- 期望：缓存或记忆化已完成消息的渲染结果，对流式增量进行批量更新，避免每个片段都重新解析全部历史消息。

### 聊天页面卸载时未自动中止流式请求
- 状态：已完成。组件卸载、切换会话和发起新请求时会自动中止旧流式请求，超时会自动停止并提示重试。
- 当前 `AbortController` 只在用户点击停止按钮时调用；页面切换、组件卸载或重新进入聊天页时，已有 Pending 流请求可能继续保留响应读取器、回调和消息闭包。
- 多次进入页面或遇到后端不结束流的情况下，可能累积未释放的请求和前端状态引用。
- 期望：在聊天组件卸载、路由切换和新请求替换旧请求时自动 `abort`，并确保请求结束后释放相关引用。

## 2026-07-22

### 聊天输入/输出区域缺少复制能力
- 状态：已完成。用户聊天页和管理员聊天页均已有消息复制与输入复制能力。
- 用户输入窗口缺少复制按钮。
- 助手输出窗口缺少复制按钮。
- 期望：每条用户输入和每条助手回答都可以单独复制，而不是只提供统一的一键复制。

### 助手输出未按 Markdown 渲染
- 状态：已完成。`MessageContent` 已支持标题、列表、代码块、表格、引用和部分行内格式。
- 当前回答内容只是按原始文本输出。
- Markdown 标题、列表、代码块、表格、引用等格式没有被渲染。
- 期望：助手回答在聊天窗口中按 Markdown 格式展示。

### 最近会话区域视觉主题不一致
- 状态：基本完成，待最终视觉复核。
- 最近会话区域目前是浅色样式。
- 期望：最近会话区域与 AidBot 外部界面整体主题保持一致。

### 最近会话展示数量和展开交互需要调整
- 状态：已完成。折叠/隐藏按钮已移除；会话列表自身保留 `max-height`/`overflow` 内部滚动限制，移动端保留 180px 限制。
- 当前最近会话展示过多或没有折叠策略。
- 期望：会话列表不要再通过折叠按钮隐藏内容，超过区域的内容由会话列表内部滚动承接，不挤压聊天主体。

### 引用调试区域用途不清
- 状态：已完成。普通用户聊天流已隐藏 `sources`/`confidence` 等调试字段；管理员点击回答下方引用来源后，通过弹窗查看来源详情。
- 当前界面中的“引用调试”区域用途不明确。
- 需要确认该区域是否面向开发调试、管理员排查，还是普通用户可见功能。
- 期望：如果不是普通用户必要功能，应隐藏、移除或移动到更合适的调试/管理员入口。

### 引用片段打分和命中可信度偏假
- 状态：基本完成，继续用评测样例扩展覆盖。
- 当前引用片段的打分看起来不够可信。
- 有些用户问题本不应该命中知识库，但系统仍然返回了引用片段。
- 这会让用户误以为回答确实有知识库依据，影响来源追溯的可信度。
- 期望：当问题与知识库内容相关性不足时，不应强行展示引用。
- 期望：引用片段需要有更可靠的相关性阈值、无命中状态或低置信度提示。

### 引用命中分数超过 1 且跨组件误命中
- 状态：已完成。引用分数已裁剪到 0 到 1，检索已有组件冲突过滤测试。
- 管理员查看引用来源时出现 `1.0340` 这类超过 1 的命中分数，分数语义不可信。
- 用户问题明确询问“主控”时，系统不应优先命中“充电底座”等不同组件的知识片段。
- 期望：引用命中分数展示范围应限制在 0 到 1。
- 期望：当问题包含明确组件实体时，候选片段如果属于另一个明确组件，且没有相同产品/故障码/版本等强实体重合，应过滤掉。

### AI 引用来源缺少知识库归属
- 状态：已完成。`SourceCitation` 已增加 `space_id` 和 `space_name`，管理员引用来源弹窗会展示知识库名称和 ID。
- 管理员后续需要专门调试某个知识库时，只看文档标题、chunk 和分数不足以判断命中边界。
- 期望：AI 引用来源中展示命中的知识库，便于排查是否命中了错误知识空间。

### 最近会话缺少删除入口和全部清空能力
- 状态：已完成。单条删除和清空全部聊天记录均已完成，用户聊天页和管理员聊天页都有入口。
- 最近会话列表只有打开会话能力，没有删除按钮。
- 用户和管理员无法从界面清理不需要的会话记录。
- 期望：每条最近会话都提供删除入口。
- 期望：最近会话区域提供清空全部聊天记录的入口。
- 期望：删除当前打开的会话后，聊天窗口回到新会话状态。
- 期望：清空全部聊天记录后，最近会话列表清空，聊天窗口回到新会话状态。
